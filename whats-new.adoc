=== Cloud Volumes ONTAP



==== Cloud Volumes ONTAP 9.19.1 dans Azure

Vous pouvez désormais utiliser la NetApp Console pour déployer et gérer la version en disponibilité générale (GA) de Cloud Volumes ONTAP 9.19.1 dans Azure.

La Console prend en charge Cloud Volumes ONTAP 9.19.1 sur AWS et Google Cloud depuis août 2026.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Notes de version de Cloud Volumes ONTAP 9.19.1"^]



==== Chiffrement Azure sur l'hôte pour Cloud Volumes ONTAP

À partir de Cloud Volumes ONTAP 9.19.1 GA, le chiffrement Azure sur l’hôte est activé par défaut pour les nouveaux déploiements Azure à nœud unique et en haute disponibilité (HA) qui répondent aux prérequis. Cette fonctionnalité chiffre les données sur le serveur physique qui héberge la machine virtuelle, y compris le disque éphémère et les caches associés au niveau de l’hôte, lors de leur écriture sur l’hôte et de leur lecture depuis celui-ci.

Avant de déployer Cloud Volumes ONTAP dans Azure, assurez-vous que votre environnement répond aux prérequis suivants :

* Cette `EncryptionAtHost` fonctionnalité est enregistrée pour votre abonnement Azure. Reportez-vous à https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Documentation Microsoft : Activer le chiffrement sur l’hôte"^].
* Le type d'instance de machine virtuelle que vous avez sélectionné prend en charge le chiffrement sur l'hôte dans votre région Azure. Reportez-vous à https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Documentation Microsoft : recherche des tailles de VM prises en charge"^].


Notez ces points :

* Aucune configuration supplémentaire n'est requise.
* Si ces conditions préalables ne sont pas remplies, le chiffrement sur l'hôte Azure n'est pas activé pour votre déploiement Cloud Volumes ONTAP.
* Le chiffrement côté hôte s'applique uniquement à Azure, et non à AWS ou Google Cloud.


Documentation Microsoft: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Utilisez le portail Azure pour activer le chiffrement de bout en bout à l'aide du chiffrement sur l'hôte"^]



==== Chiffrement du réseau back-end sur les clusters Cloud Volumes ONTAP dans Azure et Google Cloud

Cloud Volumes ONTAP 9.19.1 et les versions ultérieures prennent en charge le chiffrement du réseau de cluster back-end pour les configurations haute disponibilité dans Azure et Google Cloud.

L'activation du chiffrement du réseau du cluster peut affecter les performances du cluster. Faites preuve de prudence et assurez-vous que votre environnement peut supporter la charge supplémentaire avant d’activer cette fonctionnalité.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Activez le chiffrement du réseau back-end sur les clusters Cloud Volumes ONTAP"^]



==== Capacité à réduire les interruptions lors de la maintenance planifiée d'Azure

Lors d'une maintenance planifiée, Azure peut suspendre brièvement une machine virtuelle dans une paire haute disponibilité Cloud Volumes ONTAP. ONTAP peut interpréter cette suspension comme une panne de nœud et transférer les opérations de stockage vers le nœud partenaire, puis les rétablir lorsque la machine virtuelle reprend (basculement et rétablissement). Ce processus peut interrompre les connexions client actives, même en l'absence de panne de nœud.

Avec Cloud Volumes ONTAP 9.19.1 et versions ultérieures, vous pouvez activer un paramètre facultatif qui permet à la paire haute disponibilité de continuer à fonctionner pendant un gel de maintenance planifiée d’Azure sans lancer automatiquement le basculement et le rétablissement.


NOTE: Cette fonctionnalité est disponible en avant-première publique avec Cloud Volumes ONTAP 9.19.1.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Évitez les interruptions lors de la maintenance d’Azure pour les paires haute disponibilité Cloud Volumes ONTAP"^]

==== Améliorations des charges de travail Hyper-V

Dans cette version, les charges de travail Hyper-V introduisent les améliorations suivantes :

* *NetApp MetroCluster support*: NetApp Backup and Recovery vous permet désormais de protéger les VM Hyper-V mises en miroir par NetApp MetroCluster.
* *Protection des disques étendus pour les VM SAN* : pour les configurations CIFS et SAN, vous pouvez désormais protéger chaque disque associé à chaque VM dans un groupe de protection. Cela inclut les fichiers répartis sur plusieurs volumes ONTAP ou systèmes de stockage ONTAP (disques étendus), ainsi que les fichiers limités à un seul emplacement.


Pour plus de détails sur la protection des charges de travail Hyper-V, reportez-vous à https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-hyperv-protect-overview.html["Découvrez comment protéger les charges de travail Hyper-V avec NetApp Backup and Recovery"].



==== Amélioration des charges de travail Oracle Database

Cette version introduit l'amélioration suivante pour les charges de travail Oracle Database :

*Gestion automatique des journaux d'archivage* : lors des opérations de restauration et de clonage de base de données, NetApp Backup and Recovery détecte et monte automatiquement les journaux d'archivage requis, puis les démonte une fois l'opération terminée. Les sources de journaux de stockage primaire, secondaire et objet sont prises en charge.

Pour plus de détails sur la protection des charges de travail Oracle Database, consultez https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Découvrez comment protéger les charges de travail Oracle Database avec NetApp Backup and Recovery"].



==== Amélioration des charges de travail Microsoft SQL Server

Cette version introduit l'amélioration suivante pour les charges de travail Microsoft SQL Server:

*Modification des licences* : les frais ne s’appliquent plus aux sauvegardes utilisant une architecture disque à disque ou disque à disque en mode fan-out. Les frais s’appliquent uniquement aux sauvegardes sur stockage objet, y compris celles utilisant une architecture 3-2-1 ou disque vers stockage objet.

Pour plus d'informations sur la protection des charges de travail Microsoft SQL Server, consultez https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["Découvrez comment protéger les charges de travail Microsoft SQL Server avec NetApp Backup and Recovery"].



[[disaster-recovery]]
=== Reprise après sinistre



==== Ordre de démarrage optionnel pour les groupes de ressources Kubernetes

NetApp Disaster Recovery prend désormais en charge la définition d’un ordre de démarrage optionnel pour les groupes de ressources dans un plan de réplication Kubernetes, en spécifiant un ordre de priorité et un délai optionnel pour les ressources. Cette option vous permet de démarrer les ressources en même temps lorsque cela est nécessaire et de différer le démarrage des ressources qui dépendent d’autres ressources, afin que vos applications reviennent en ligne de manière saine.

Pour plus d'informations, consultez link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/drplan-create.html["créer un plan de réplication"^].



==== SnapLock prise en charge des volumes

La reprise après sinistre prend désormais en charge les volumes SnapLock, ce qui vous permet de basculer vers des copies Snapshot inviolables.. Lors de l'exécution d'un rétablissement avec des volumes SnapLock, vous devez utiliser l'option *Take snapshot now* pour garantir la réussite du rétablissement.

Pour plus d'informations, consultez les instructions pour link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["basculement"^] et link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["retour arrière"^].



==== Exécutions simplifiées d’actualisation et de conformité

Les actualisations pour vCenter, les plans de réplication et la conformité ont été simplifiées en une seule tâche afin de permettre une exécution plus rapide. Pour voir cette modification, découvrez comment link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["surveiller les tâches"^].



==== Contrôles de conformité Kubernetes

Disaster Recovery a ajouté des contrôles de conformité pour identifier les environnements de travail manquants pour les charges de travail Kubernetes. Ces contrôles de conformité contribuent à garantir l'état de santé des charges de travail afin de préserver l'intégrité de vos plans de réplication.

==== Améliorations des charges de travail des volumes ONTAP

Dans cette version, les workloads ONTAP Volumes introduisent les améliorations en avant-première suivantes :

* *Prise en charge améliorée des sites distants* : NetApp Backup and Recovery pour les sites distants offre désormais les mêmes fonctionnalités de protection des données ONTAP Volumes que NetApp Backup and Recovery. Cette amélioration comprend des services de sauvegarde, de restauration et de gestion des tâches mis à jour, ainsi qu'une nouvelle base de données. Lors d'une mise à niveau, les données de la base de données existante sont conservées et migrées automatiquement. Après la mise à niveau, consultez les journaux d'audit pour vérifier que la migration s'est déroulée correctement. NetApp Backup and Recovery pour les sites distants prend uniquement en charge les charges de travail ONTAP Volumes.
* *Annulation des tâches de restauration de volumes* : Vous pouvez désormais annuler les tâches de restauration de volumes ONTAP en cours depuis la page de surveillance des tâches, ce qui facilite la gestion des tâches longues ou lentes.
* *Amélioration du rapport sur l’état d’indexation des volumes* : Le tableau de bord ONTAP Volumes rapporte désormais l’état d’indexation avec plus de précision en introduisant le statut  `Not Applicable` pour les volumes et les copies d’instantané qui ne sont pas éligibles à l’indexation. Le statut  `Not Indexed` est désormais réservé aux volumes en attente d’indexation, et les détails du volume affichent maintenant l’état d’indexation de chaque instantané avec une infobulle expliquant pourquoi un volume ou une copie d’instantané ne sera pas indexé.
* *Prise en charge de NetApp AFX* : Vous pouvez désormais protéger les volumes hébergés sur des clusters NetApp AFX à 2 et 4 nœuds.


Pour plus de détails sur la protection des charges de travail ONTAP Volumes, reportez-vous à https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Découvrez la protection des volumes ONTAP avec NetApp Backup and Recovery"].

[[ransomware-resilience]]
=== Résilience aux ransomwares



==== Standardiser les groupes de protection en fonction de la charge de travail et du type de système

La fonctionnalité de résilience aux ransomwares impose désormais que les groupes de protection ne comprennent qu'un seul type de charge de travail et un seul type de système. Lorsque vous créez un nouveau groupe de protection, vous devez désigner à la fois le type de charge de travail (système de fichiers ou bloc) et le système pour la charge de travail. Cette amélioration garantit que la stratégie de protection contre les ransomwares choisie pour le groupe de protection peut être appliquée avec succès à toutes les charges de travail du groupe.

Si vous avez des groupes de protection existants qui mélangent des types de systèmes et de charges de travail, vous pouvez continuer à les utiliser, mais vous ne pouvez pas ajouter de charges de travail au groupe de protection.

Pour plus d'informations, consultez link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-protection-group.html["Créer un groupe de protection"^].



==== Amélioration des exercices de préparation

Ransomware Resilience vous permet désormais d'effectuer des exercices de préparation en fonction du type d'attaque. Ransomware Resilience détecte cinq types d'attaques et vous permet de réaliser des exercices de préparation pour chacune d'elles afin de simuler le processus d'attaque et de récupération et ainsi évaluer votre niveau de préparation face à une attaque de ransomware.

Pour plus d'informations, consultez link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-start-simulate.html["Effectuer un exercice de préparation"^].



==== Mettre en pause ou supprimer un système SIEM

Ransomware Resilience propose désormais dans son interface utilisateur des options permettant de suspendre ou de supprimer un système SIEM. Cette amélioration facilite la désactivation temporaire du système à des fins de dépannage ou de maintenance ou sa suppression définitive.

Pour plus d'informations, consultez link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-siem.html#disable-a-siem-system["Désactiver un système SIEM"^].

==== Prise en charge de la région Chile Central dans Azure

Vous pouvez désormais déployer Cloud Volumes ONTAP 9.12.1 GA et versions ultérieures dans la région Chile Central (chilecentral) dans Azure. Les types de déploiement suivants sont pris en charge :

* Nœud unique
* HA dans une seule zone de disponibilité avec un stockage localement redondant (LRS)
